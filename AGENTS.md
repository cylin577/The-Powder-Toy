# Repository Guidelines

## Build
Meson/Ninja. C++20, RTTI off, asserts disabled (`b_ndebug=true`).

- `meson setup build` — configure.
- `meson compile -C build` — builds the main `powder` executable.
- `meson setup build-clangtidy -Dclang_tidy=true` && `meson compile -C build-clangtidy clang-tidy` — lint (only check enabled: `modernize-use-nullptr`, warnings-as-errors).

Quirks:
- Default `static=none` uses system libs: `luajit` (or `-Dlua=lua5.1/5.2`), `fftw3f`, `jsoncpp`, `sdl2`, `libpng16`, `bzip2`. `-Dstatic=prebuilt` uses official prebuilt `tpt-libs` subprojects.
- System Lua without a C++ binding fails configure; use `-Dworkaround_noncpp_lua=true`.
- `build-release/` is a CI-oriented configuration, not a local dev build; reconfigure it rather than inventing ad hoc scripts.
- Non-desktop targets exist (`render`, `font`, emscripten); not all options apply everywhere — check `meson_options.txt`.

## Project Structure
`src/` is the C++20 app: `src/simulation/` (physics + elements in `src/simulation/elements/*.cpp`), `src/gui/` (UI), `src/client/` (saves/networking), `src/common/` (shared utils), `src/lua/` (scripting). Meson definitions are split across `meson.build` files throughout the tree. `docs/wiki/` is generated by `npm run export:wiki` — don't hand-edit generated output.

## Coding Style
Follow surrounding C++ style exactly: tabs for indentation, opening braces on a new line, include blocks grouped like nearby files. `PascalCase` types/methods, `camelCase` locals, uppercase element ids like `PT_WATR`. Don't mass-reformat unrelated code.

## Testing
No unit-test suite; CI is build-only. Verify by compiling and targeted runtime checks (element changes in-game, UI changes in the relevant screen/dialog). Mention manual verification steps in the PR.

## Commits & PRs
Short imperative subjects (`Add api for controlling textbox focus`, `Appease clang-tidy`); keep commits focused, don't mix refactors with behavior changes. PRs need a concise description, reason for change, and manual test notes; screenshots/recordings for visible UI changes. Discuss large PRs (e.g. new elements) with the dev team on Discord/IRC first — some may be rejected.
